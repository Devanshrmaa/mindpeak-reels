## Executive Summary

The week-2 dev fixes (HTTP 410 for 18 doorways, sitemap cleanup, `lastmod` refresh) shipped on 2026-05-18 but recovery has **not yet moved** — and a live `site:` sweep this week exposed **why**, plus two code-level signal defects that were actively working against de-indexing:

1. **A site-wide `X-Robots-Tag: index, follow` HTTP header** (set on `source: '/(.*)'` in `next.config.ts`) was being sent on **every URL — including all ~472 noindexed doorway pages**. So each doorway returned a `<meta robots noindex>` in its HTML *and* an `X-Robots-Tag: index` in its HTTP header. This is the exact conflict Google warns about: "noindex in the meta tag and index in the HTTP header can confuse search engines and lead to improper indexing." The header was telling Google to keep the very pages we are trying to remove.

2. **`noindex` for the doorway pages lived only in the rendered HTML `<meta>` tag.** Google must fetch *and render* a page to see a meta tag — and under penalty crawl-throttling that is not happening at scale. The 18-URL 410 list was the only header-level signal, and it does not scale to the hundreds of remaining doorways (e.g. `/jee-coaching-in-andheri`, surfaced fresh this week, was on no list).

Both are now fixed in code (see §9). The conflicting header is removed, and **every** doorway `coaching-in-` URL now emits `X-Robots-Tag: noindex, follow` at the HTTP layer — a directive Google can act on from a plain crawl, no render required.

**Overall Status: 🟠 STALLED but ROOT-CAUSED — two signal defects fixed; recrawl now the only remaining gate**

## 9. Fixes Applied (2026-05-28)

### 9.1 Removed the conflicting site-wide `index` header
`next.config.ts` previously sent `X-Robots-Tag: index, follow` on `source: '/(.*)'` — every URL, including all noindexed doorways. Indexing is Google's default, so the header added nothing for legitimate pages while directly contradicting the doorways' `<meta robots noindex>`. **Removed.** Indexable pages now rely on the default (no header); doorways get an explicit `noindex` header from the proxy.

### 9.2 Pattern-based header `noindex` for all doorways (`proxy.ts`)
The proxy now, in addition to the existing 410 for the 18 confirmed-dead URLs:
- emits `X-Robots-Tag: noindex, follow` for **any** `coaching-in-` slug that is not a curated T1 city or national flagship page;
- runs on all content routes (matcher broadened from 18 literal paths to `'/((?!_next/|api/|.*\\.).*)'`).

This gives Google a header-level de-index signal it can honour **without rendering** — covering the ~472 expansion cities + subject-city combos at once, including future ones, instead of a hand-maintained list.

### 9.3 Single source of truth — `src/lib/indexableCities.ts`
Extracted `INDEXABLE_CITY_META` out of `resolveSlugMetadata.ts` into a shared, edge-safe module that also exports `INDEXABLE_CITY_SLUGS`, `INDEXABLE_NATIONAL_COACHING_SLUGS`, and `isDoorwayCoachingSlug()`. Both the metadata resolver (`<meta robots>`) and the proxy (`X-Robots-Tag`) import the same set, so the indexable list can never drift between the two layers — eliminating the risk of a T1 city accidentally getting a `noindex` header (verified: Bangalore, Delhi NEET, and `/best-jee-coaching-in-india` all stay header-free).
